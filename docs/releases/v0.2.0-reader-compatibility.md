# v0.2.0 targeted Test reader compatibility

Rustrace [v0.2.0](https://github.com/baochunli/rustrace/releases/tag/v0.2.0),
published November 12, 2026, adds Cargo integration tests to F4 and the command
`cargo test --test TARGET FILTER -- --exact`. Older readers reject recordings
containing that command. Existing assignment packages do not need repacking;
updated readers still accept historical recordings.

## Deployment gate

A release being available through `rustrace update` is not evidence that the
staff grader, verifier, scan, or replay executables have been updated. Before
processing affected submissions, the staff deployment owner should record:

| Installation | Executable path | Version and build commit | Targeted-Test submission verified and replayed | Historical submission verified |
| --- | --- | --- | --- | --- |
| Each actual staff workflow | Record the executable the job invokes | `rustrace --version --verbose`; 0.2.0 or later compatible build | Result and reference package | Result |

Check job environments and explicitly configured executable paths, not only
an interactive shell's PATH. Run the representative new submission against
the unchanged course `.rta`, then inspect its command and output in replay.
Do not remove command arguments or weaken validation to make an old reader
accept new recordings. Preserve the original submission, upgrade the reader,
and retry. A reader compatibility error does not by itself establish corrupt
student work.

This repository does not inventory deployed staff machines. No fleet-wide
readiness or failed student submission is established by this document.

## Assignment 3 handout check

The course's Lab 3 format-3 package, assignment version `2026f-2`, contains two
packaged help-output cases and ten public Rust tests in
`starter/tests/public_cli.rs`. Rustrace 0.1.8–0.1.9 shows only the help cases in
F4; 0.2.0 also discovers those ten Rust tests and includes them in Run all.
The Rust tests can start their own local HTTP servers. The two help cases
already pass in the unfinished starter and are not graded; the ten public
functional tests are expected to fail until implemented.

Keep handout instructions version-qualified. An old two-case PTY check or a
successful verification with 0.1.9 does not validate targeted-Test recordings
or establish readiness of the newer reader deployment.
